# FlusGrid 0.5.0 — start a 2,048×2,048 preparation run

For Nether/End, use [the dimension guide](DIMENSIONS.md). These commands prepare the Overworld.

Use a backed-up Creative test world, before inviting Survival players. This is a larger experimental preparation build, not a finished survival release.

## Install

Pause any active old job first. Exit the world, remove the earlier FlusGrid ZIP from its `datapacks` folder, and install only `FlusGrid-0.5.0-experimental.zip`, unextracted. Reopen the world.

If the pack is available but not enabled:

```mcfunction
/datapack enable "file/FlusGrid-0.5.0-experimental.zip"
```

Wait for the pack to load. In Creative, fly above the desired center and run:

```mcfunction
/function flusgrid:pregen_2048_here
```

This selects a chunk-aligned 2,048×2,048 square, full height -64..319: 16,384 chunks and 393,216 vertical cubes. The minimum corner is your current chunk minimum minus 1,024 on both X and Z. Starting in chunk 0,0 therefore prepares X/Z -1024..1023.

The existing `/function flusgrid:pregen_here` still means 512×512. The explicit large minimum-corner API is:

```mcfunction
/function flusgrid:pregen_2048_start {x:-1024,z:-1024}
```

Choose ONE start command. An active/paused job cannot be replaced; an old paused 512 job must finish first or use a fresh test world. Repeated prepared cubes are skipped, so work is not erased.

## While it works

```mcfunction
/function flusgrid:status
/function flusgrid:pause
/function flusgrid:resume
```

Keep the world running and unpaused. Resume explicitly after reopening/reloading. At normal speed the theoretical minimum with the current one-cube-per-tick design is 5 hours 41 minutes 20 seconds, before generation waits and lag. A complete 2048 run has NOT been timed or completed in developer testing; the earlier full 512 run passed. This build supports the larger job but is not an optimization release.

After completion, inspect terrain and back up the world before further changes. There is no automatic border, start platform or safe survival spawn yet. Terrain outside the square stays normal.

## Leaves: what changed

Before clearing a new cube, retained vanilla leaves are set to `persistent=true`. All 14 leaf species in the shipped Java 26.3 leaves tag are covered, including poplar colors. Species, distance and waterlogging are preserved. This explicitly prevents normal leaf decay rather than relying on strict edits alone. Player mining, fire and explosions can still destroy persistent leaves.

When this version passes through a previously completed cube during area/pregen preparation, it performs a leaf-only persistence repair at the grid positions without clearing the cube again. It cannot restore leaves that already decayed. Custom datapacks adding other leaf species are not covered by the vanilla species list.

## Other physics are not frozen

Grass can change, farmland can dry out, unsupported plants can break, sand/gravel can fall, and fluids can flow when they receive updates. Existing scheduled ticks also remain. Strict conversion suppresses immediate neighbor updates; it does not permanently disable Minecraft's simulation.

This build deliberately does not set random ticks to zero globally, which would also stop normal crop growth and other survival behavior. The leaf fix is specific. Further physics/progression work is required before this is a survival release; do not treat completion as a guarantee that every surviving block stays unchanged forever.
